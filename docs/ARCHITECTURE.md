# Architecture

## Overview

Four bun workspaces in TypeScript, ESM, with no compile step. The indexer and agent run through `tsx` or Node's type stripping, and the web app through Vite.

```
shared/   @fiada/shared    the graph contract both sides import: nodes, edges and their evidence, layers, grouping, agent events (src/index.ts)
indexer/  @strata/indexer  Fastify server on 127.0.0.1:4178 and a CLI: clone → parse → link → facts → build → classify
web/      @fiada/web       React 19 + Vite on :5178 (proxies /api to the indexer): canvas map, sidebar, detail panel, agent window
agent/    @fiadatech/agent what a coding agent runs: a tool-hook CLI and a stdio MCP server that report edits to the indexer; published to npm
```

What runs where:

```
browser ── https://fiada.tech ─────────────── static map (web/dist), Cloudflare Workers
   └────── VITE_API_URL ── https://<indexer> ── indexer container (Railway) ── /data: accounts, projects, clones
                                                     └── MongoDB Atlas, only if MONGODB_URI is set
coding agent ── hook + MCP server (@fiadatech/agent) ── POST /api/agent/* on the indexer
```

The map is a static build. The indexer is a long-running server that clones repositories to disk, parses them, keeps the graph in memory and streams agent activity over SSE, so it can't run on Workers ([ADR 0002](adr/0002-indexer-in-a-container.md)).

## Code map

- `indexer/src/server.ts`: every HTTP route (`/api/auth*`, `/api/workspace`, `/api/graph`, `/api/repos`, `/api/grouping`, `/api/source`, `/api/summary`, `/api/agent/*`, `/api/admin/stats`), and the one `onRequest` hook that decides who is asking and which project (`req.tenant`) they work in.
- `indexer/src/auth.ts`: GitHub sign-in, signed session and agent tokens, sealed GitHub tokens. `indexer/src/tenants.ts`: one project per signed-in person (or the one shared project), opened on demand and closed after 30 idle minutes.
- `indexer/src/access.ts`: who may call what (`whoMayCall`), and `RateLimit`. `indexer/src/stats.ts`: the owner's usage counts.
- `indexer/src/workspace.ts`: one project, its repos, clones, parsed facts, grouping and the combined graph. `parseSource` decides what may be cloned.
- `indexer/src/sources.ts`: lists files with `git ls-files`, skips vendored and generated directories and (by default) tests, reads `package.json`, `tsconfig*.json`, `pyproject.toml` and `requirements*.txt`. `fileWithin` is the only way to read a file in a clone or upload.
- `indexer/src/upload.ts`: folder uploads, unpacked into the indexer's storage and indexed like a clone.
- `indexer/src/parse/`: tree-sitter (WASM) extractors for TypeScript, TSX, JavaScript, Python, Go, Java, Kotlin, C#, Rust, C, C++, Ruby and Swift. A language is a grammar in `treesitter.ts`, an extension in `index.ts` and one extractor. The declaration-shaped languages share the walk in `outline.ts`.
- `indexer/src/link.ts`: resolves imports, calls, router mounts and HTTP requests into edges with evidence, and how each language finds names across files (packages, namespaces, modules, includes).
- `indexer/src/facts.ts`: turns what the parser saw into language-neutral facts on every file and symbol. `indexer/src/build.ts`: the node tree (single-child folder chains collapsed) and edges.
- `indexer/src/classify/`: layers and domains from facts, paths and edges. Presets in `presets.ts`, domain seeding in `propagate.ts`, strategies in `index.ts`, the model sort in `model-sort.ts`, its saved result in `sorted.ts`.
- `indexer/src/summaries/`: per-node summaries, a line from the graph or generated by the model and cached by content hash.
- `indexer/src/llm.ts`: the one model client, and `LLMBudget`. `indexer/src/store.ts` and `mongo-store.ts`: persistence.
- `indexer/src/agents.ts`: `AgentHub`, which turns hook and MCP events into changes on the graph, answers an agent's check before an edit, and finds where two agents' changes meet (`collisions`). `indexer/src/ask.ts`: the read tools' answers.
- `indexer/src/fences.ts`: fences, circles marked "ask first" or "off limits", kept per project.
- `indexer/src/env.ts` and `agent/src/env.ts`: read every `FIADA_*` variable, and its `STRATA_*` alias.
- `web/src/render/renderer.ts`: the canvas renderer (camera, animation, pointer input, hit testing). `render/edges.ts`: which links are drawn and where they bend (`EdgePolicy`). `render/activity.ts`: the agent overlay (rings, pulses, count badges, where agents meet). `render/fences.ts`: fence lines and hatching.
- `web/src/graph/`: tree building, layout, camera maths, edge lifting (`view.ts`), agent change roll-ups (`activity.ts`) and the review tour (`tour.ts`).
- `web/src/components/`: React panels (`Sidebar`, `Detail`, `AgentQueue`, `AgentChange`, `TopBar`, `MapView`, `Privacy`).
- `web/src/theme/tokens.css`: every colour and type token. `tokens.ts` hands them to the canvas.
- `agent/src/cli.ts` (the `fiada` command) dispatches to `hook.ts`, `mcp.ts` and `setup.ts`. `agent/bin/*.mjs` run it from source in a checkout, or from the esbuild bundle `agent/dist/cli.js` in the published package (`agent/build.mjs`).

## The indexer pipeline

1. **Sources** (`sources.ts`) lists and reads the files.
2. **Parse** (`parse/`) extracts imports, top-level symbols, the identifiers each symbol uses, server routes and the routers they hang off, client HTTP requests, client page routes (React Router, TanStack Router) and ORM links (SQLAlchemy relationships and foreign keys, GORM fields). TypeScript, TSX, JavaScript, Python and Go get the most depth. Java, Kotlin, C#, Rust, C, C++, Ruby and Swift get their types and methods (as `Type.method`), what each uses, and the routes of Spring, JAX-RS, ASP.NET controllers and minimal APIs, and actix/Rocket attributes.
3. **Link** (`link.ts`) resolves imports (relative paths, tsconfig `paths`, workspace packages, Python packages, Go modules, Java and Kotlin packages, C# namespaces, Rust `use` paths and `mod` files by Cargo crate, C and C++ includes, Ruby requires, across every imported repo). It finds the names a language shares without an import, binds identifiers to symbols through re-exports and barrels, follows router mounts (`include_router`, `register_blueprint`, `app.use`, gin groups) to give every route its full path, and matches requests like `` fetch(`${API}/items/${id}`) `` to routes like FastAPI's `@router.get("/{id}")` under `APIRouter(prefix="/items")`. Every edge records the code behind it (file, line, text) and whether it is **evidenced** (the code names the target, or a request's full path equals the route's) or **inferred** (a heuristic linked them), with a confidence and a one-line reason.
4. **Facts** (`facts.ts`): the routes a node serves, the requests it makes, JSX, ORM tables, base classes, decorators, imports, and whether it is type-only.
5. **Build** (`build.ts`) emits the node tree and edges.
6. **Classify** (`classify/`) places every file and symbol in one of the project's layers and a domain, each with evidence. It reads only facts, paths and edges, so a grouping change reclassifies in milliseconds without re-parsing.
7. **Sort and summarise**, off the request path and only with a model key: `model-sort.ts` names and merges domains and places what the rules couldn't, and `summaries/` writes summaries in batches, files first, then folders deepest first, domains, layers and repositories.

## The map

The web app rebuilds the tree for the chosen view (**code**, or **by function**: domain, then layer) and decides which circles are open: the ones you opened (click mode), or the ones big enough on screen (zoom mode). It packs only the open part of the tree, giving each closed circle a compact size, and lifts every edge to the nearest visible ancestor of each end, so edge thickness follows the number of underlying interactions. Each edge bends whichever way crosses the fewest closed circles, worked out once per layout. Edges resolve to tree indices once per graph, so re-lifting when something opens takes a couple of milliseconds even on next.js.

The map draws to a canvas, and React hands the renderer a new scene only when what's open or selected changes, so zooming and panning never re-render the app. The SVG map it replaced dropped to 15 to 20 fps on next.js (13k nodes, 10k edges), with stalls of up to 1.7 s whenever circles opened, most of it the browser painting SVG and label DOM.

## Data

- **Projects** go through `ProjectStore` (`indexer/src/store.ts`): repositories, grouping (`fiada.grouping.json`, with the model's `sorted` result), summaries, fences (`fences.json`) and accounts. `FileProjectStore` writes under `$FIADA_HOME/projects/<id>/` and `$FIADA_HOME/accounts/<id>.json`. `MongoProjectStore` (`mongo-store.ts`) is used when `MONGODB_URI` is set: one document per project in `projects`, plus `accounts` and `summaries`, in the database `strata`. The README's Storage section says how two indexers share a project. See [ADR 0001](adr/0001-file-store-not-supabase.md).
- **Clones and uploads** stay on the indexer's disk (`$FIADA_HOME/clones/`, per person `clones/gh-<GitHub user id>/`) in either store. The graph is always derived and never stored.
- **Agent activity** lives in memory in `AgentHub` only. Dismissing an agent clears its marks, and a restart forgets them.
- **The browser** keeps the theme, the API key and view settings in `localStorage` (`strata-theme`, `strata.key`, `strata.expandMode`, `strata.layersOpen`, `strata.queueCollapsed`, the session `fiada.session`). Read marks live per project in `fiada.read.<project>`, counted per agent, and review tour state under `fiada.tour.*`. Both are cleared when the account is deleted.
- **The hook** keeps each session's last view of the working tree under `$FIADA_AGENT_STATE` (default `$TMPDIR/fiada-agent`). `fiada setup` saves the indexer URL and token in `~/.config/fiada/agent.json`.

## Agents

- The hook (`agent/src/hook.ts`) runs on SessionStart, UserPromptSubmit, PostToolUse (Edit, Write, MultiEdit, NotebookEdit, Bash, TodoWrite, the task tools, Read), Stop and SessionEnd. It trusts git, not the tool input: it diffs the working tree against a per-session snapshot, so shell `rm` and `mv` and generated files are caught.
- A PreToolUse hook on Edit, Write, MultiEdit and NotebookEdit asks `POST /api/agent/check` about fences before the edit lands. Shell commands aren't checked, and the map's copy says so.
- The MCP server (`agent/src/mcp.ts`) gives the agent `status`, `flag_changes`, and the read tools `where_is`, `who_uses` and `impact`, which call `GET /api/agent/find`, `/dependents` and `/impact`.
- Each request to the indexer gives up after 1.5 s and the hook always exits 0. Its git commands can take up to 10 s each, and Claude Code gives each hook 10 s, so a slow checkout can still stall an edit for a few seconds.
- `AgentHub` matches an agent to an imported repository by local path, then `origin` remote, then folder name. It re-parses changed files in a checkout it reads in place, diffs symbols against HEAD's parse, and streams state to the map over SSE. On a hosted indexer, changes land on the clone of the same repository and ring only files and symbols that exist at HEAD.

## External services

- **Cloudflare Workers** serves the map as static assets: Worker `fiada-web` (`wrangler.jsonc`), built by Workers Builds from `main`, at https://fiada.tech and `https://fiada-web.<account>.workers.dev`. Builds carry Cloudflare's Web Analytics beacon. `web/public/_headers` holds the Content-Security-Policy.
- **Railway** runs the indexer from the root `Dockerfile` (Node 22, bun for install): project `aware-ambition`, service `@strata/indexer`, at https://strataindexer-production.up.railway.app. It has the variables `PORT`, `FIADA_PROJECT=demo`, `FIADA_ALLOWED_ORIGINS`, `FIADA_API_KEY`, `FIADA_SESSION_SECRET`, `FIADA_GITHUB_CLIENT_ID`, `FIADA_GITHUB_CLIENT_SECRET`, `ANTHROPIC_API_KEY` and `RAILWAY_RUN_UID=0`, and the 500 MB volume `fiada-data` on `/data`. There is no `MONGODB_URI`, so hosted data is files on that volume. Values live only in Railway.
- **GitHub OAuth** signs people in, with the `repo` scope for private repositories. Hosted sign-in is on: `/api/auth` answers `{"mode":"github"}`.
- **Anthropic** (`claude-haiku-5-5`) sorts and summarises, through `indexer/src/llm.ts`. OpenAI answers only when its key is the only one set, or `FIADA_LLM_MODEL` names an OpenAI model. Nothing needs a key to work.
- **MongoDB Atlas** is optional and unused in production since 2026-10-25.
- **npm** hosts `@fiadatech/agent`.
